# Платформа мобильного робота (Student Robotics Platform)

Открытая платформа для управления мобильным шасси, объединяющая сенсорный комплекс, веб-пульт оператора и модульный API для студенческих исследовательских работ.

---

## 🎯 Цель проекта
Оживить существующее физическое шасси робота, настроить управление движением, подключить базовый комплекс сенсоров (лидар, камеры, гироскоп), разработать удобный веб-пульт оператора на React и предоставить открытый программный интерфейс (API + плагины), чтобы следующие студенты могли сразу писать прикладные алгоритмы (автономную навигацию, компьютерное зрение), не тратя время на настройку «железа».

---

## 📋 Задачи, шаги реализации и критерии валидации

Для каждого этапа определены конкретные действия и измеримые критерии приемки (Definition of Done), по которым можно проверить работоспособность.

### 1. Шасси и управление движением
* **Что нужно сделать:**
  1. Определить распиновку и подключить плату управления моторами (H-мост / драйвер) к контроллеру (ESP32 / STM32 / Arduino / Raspberry Pi).
  2. Подключить энкодеры колес для считывания реальной скорости и пройденного расстояния.
  3. Реализовать дифференциальную/омни кинематику: преобразование общей линейной ($v$) и угловой ($\omega$) скорости в обороты левого и правого колес.
  4. Настроить ПИД-регулятор скорости для удержания прямолинейного движения.
  5. Реализовать аварийный останов (Watchdog / E-Stop): если от пульта нет команд дольше 500 мс, моторы автоматически обесточиваются.
* **Критерии валидации (как проверить):**
  - [ ] По команде «проехать 1 метр вперед» робот останавливается с отклонением не более 5 см.
  - [ ] Робот едет по прямой линии без заваливания в сторону.
  - [ ] При закрытии вкладки пульта или обрыве Wi-Fi робот останавливается менее чем за 0.5 секунды.

---

### 2. Сенсорный комплекс
* **Что нужно сделать:**
  1. **Лидар (2D/3D LiDAR)**:
     - Подключить лидар по USB/UART/Ethernet.
     - Написать/интегрировать драйвер для считывания углов и дистанций, фильтрации выбросов и формирования 360-градусного массива расстояний.
  2. **Камеры**:
     - Подключить курсовую USB/CSI-камеру.
     - Настроить видеостриминг с низкой задержкой (MJPEG / WebRTC / H.264) для отображения на веб-пульте.
  3. **Гироскоп и акселерометр (IMU)**:
     - Подключить датчик (MPU6050 / BNO055 / аналогичный) по I2C/SPI.
     - Настроить калибровку смещения нуля (калибровка гироскопа при старте).
     - Применить алгоритм комплементарного фильтра / Маджвика для получения стабильных углов крена (Roll), тангажа (Pitch) и рыскания (Yaw).
* **Критерии валидации (как проверить):**
  - [ ] Лидар выдает массив сканирования с частотой не менее 5-10 Гц. Если поставить препятствие на расстоянии 1.0 м, в данных четко видна точка на удалении $1.0 \pm 0.05$ м.
  - [ ] Видеопоток стабильно отображается с задержкой не более 200–300 мс при разрешении не ниже 720p/15-30 fps.
  - [ ] При физическом наклоне корпуса робота показания углов IMU меняются плавно, без накопления дрейфа в покое.

---

### 3. Режим работы без физического робота (Mock / Имитация)
*Для возможности разработки и тестирования дома или в аудитории без подключения к «железу».*
* **Что нужно сделать:**
  1. Встроить флаг переключения режима (например, `ROBOT_MODE=mock` или `ROBOT_MODE=real`).
  2. В режиме `mock`:
     - Синтезировать фиктивный скан лидара (виртуальная прямоугольная комната со стенами).
     - Генерировать тестовый видеопоток (изображение с веб-камеры ПК либо тестовая сетка с таймером).
     - Имитировать показания гироскопа и плавный разряд аккумулятора.
     - Интегрировать виртуальные координаты робота при получении команд движения.
* **Критерии валидации (как проверить):**
  - [ ] Вся система (сервер и пульт) запускается на обычном ноутбуке без ошибок подключения к портам.
  - [ ] Веб-пульт отображает живые данные телеметрии и реагирует на нажатия клавиш.

---

### 4. Веб-пульт оператора на React
* **Что нужно сделать:**
  1. Развернуть клиентское приложение на React (Vite / Next / CRA).
  2. Сверстать адаптивный интерфейс оператора:
     - Окно видеопотока с камеры в реальном времени.
     - Интерактивный 2D-радар для отображения точек с лидара (Canvas / SVG).
     - 3D или 2D индикатор ориентации робота по данным IMU (искусственный горизонт).
     - Индикатор напряжения и процента заряда батареи, статус связи (пинг).
     - Виртуальный сенсорный джойстик (для смартфонов/планшетов) + обработчик клавиатуры (WASD / стрелки) и геймпада.
     - Кнопка аварийного торможения (E-Stop).
  3. Организовать постоянный двусторонний обмен данными с сервером по WebSocket.
* **Критерии валидации (как проверить):**
  - [ ] Страница пульта открывается в браузере с компьютера и со смартфона по локальной сети.
  - [ ] Задержка передачи команды с пульта на сервер составляет менее 50 мс.
  - [ ] Графика лидара и IMU рендерится плавно (30+ FPS) без зависания интерфейса.

---

### 5. Открытый программный интерфейс (API + Плагины для студентов)
* **Что нужно сделать:**
  1. Зафиксировать формат сообщений обмена (JSON через WebSocket / REST API):
     - Входные команды: `cmd_vel` (`linear_x`, `angular_z`), `e_stop`.
     - Выходная телеметрия: `imu`, `lidar_scan`, `battery_voltage`, `wheel_odometry`.
  2. Написать легковесную библиотеку-клиент (SDK) на Python:
     - Простая подписка на датчики через функции обратного вызова (callbacks).
     - Методы отправки команд движения `robot.drive(linear, angular)`.
  3. Подготовить базовые примеры плагинов для студентов:
     - `example_obstacle_avoidance.py` — простой алгоритм обхода препятствий по лидару.
     - `example_lane_tracking.py` / `example_yolo_detector.py` — обработка кадров камеры.
* **Критерии валидации (как проверить):**
  - [ ] Студент может за 5 минут установить SDK, запустить тестовый скрипт из 15 строк и увидеть отклик робота.
  - [ ] Алгоритм обхода препятствий успешно останавливает или отворачивает робота при приближении к преграде.

## 🛠️ Первые практические шаги для старта
1. **Инвентаризация железа**: зафиксировать точные модели компонентов (драйвер моторов, марка лидара, интерфейс камеры, модель IMU, управляющий микроконтроллер).
2. **Создание каркаса бэкенда**: поднять минимальный WebSocket-сервер с поддержкой моковых данных (`ROBOT_MODE=mock`).
3. **Создание базового веб-пульта на React**: подключить WebSocket и вывести значения джойстика и тестовой телеметрии.
4. **Поэтапное подключение реальных датчиков**: заменять моковые модули на реальные драйверы по мере готовности железа.
